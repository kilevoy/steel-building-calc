# Инженерная память проекта

`knowledge/` хранит инженерный контекст проекта `steel-building-calc`: структуру модулей, принятые решения, временные допущения, связь с Excel/VELICAN-оракулами и правила работы для будущих AI-агентов.

Эта папка не заменяет исходный код и тесты. Код остаётся источником реализации, тесты — автоматической проверкой поведения, а `knowledge/` — источником понимания: почему решения были приняты, что уже проверено и что требует отдельной инженерной верификации.

`knowledge/raw/` предназначена для описания исходных материалов: Excel, КМ-проектов, нормативных документов и скриншотов. Тяжёлые и конфиденциальные файлы по умолчанию не коммитятся.

## Рабочая папка проекта

Рабочий git-клон проекта должен храниться на локальном диске:

```text
C:\steel-building-calc
```

Синхронизируемые облачные папки Google Drive, Dropbox и OneDrive больше не используются как рабочее место для кода. Они могут создавать служебные файлы внутри `.git/`, конфликтовать с `node_modules/` и ломать `git fetch`, `npm install`, `lint` или `build`.

GitHub остаётся единственным источником синхронизации кода между домом и работой:

1. Перед началом работы выполнить `git pull`.
2. После завершения изменений выполнить проверки.
3. Сделать `git commit`.
4. Выполнить `git push origin main`.
5. На другом компьютере снова начать с `git pull`.

## Где хранить исходники

Тяжёлые raw-источники не должны лежать в рабочем клоне как отслеживаемые файлы. Их можно хранить отдельно, например:

```text
C:\steel-building-sources
```

или в Google Drive, если нужна синхронизация Excel/PDF/КМ между компьютерами:

```text
G:\Мой диск\steel-building-sources
```

В `knowledge/raw/source-register.md` нужно фиксировать ID источника, место хранения и назначение. В Git коммитятся только описания, выводы, обезличенные заметки и маленькие тест-кейсы. Excel, PDF, DWG, DXF, ZIP и похожие файлы по умолчанию не коммитятся.
