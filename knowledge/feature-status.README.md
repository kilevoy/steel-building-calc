# Канонический трекер user stories

Единый файл трекинга: `knowledge/feature-status.csv`.

Правила работы:

- одна строка CSV соответствует одной user story или одному наблюдаемому пользовательскому поведению;
- `expected_behavior_based_on_code` описывает ожидаемое поведение только на основании текущего кода;
- `test_status` меняется по циклу: `not-tested` -> `tested-pass` / `tested-fail`;
- `issue_status` хранит краткое описание найденной ошибки или `none`;
- `fix_status` меняется по циклу: `not-started` -> `fixed` / `not-needed`;
- `retest_status` меняется после исправления: `not-started` -> `tested-pass` / `tested-fail`;
- если поведение спорное инженерно, это фиксируется в `notes` и в соответствующей странице `knowledge/wiki/`.

После полной инвентаризации следующий цикл:

1. тестировать user stories по порядку;
2. документировать ошибки в этом CSV;
3. исправлять только логистические и UX-ошибки без изменения расчётных формул;
4. повторно тестировать исправленное поведение;
5. обновлять статусы в CSV.
