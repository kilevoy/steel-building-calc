# План тестов перед разделом "Единое здание"

Цель: не начинать общий раздел здания, пока базовые модули не имеют понятной Excel-parity защиты.

## Минимум перед началом

1. Оставить зелеными текущие acceptance tests:
   - колонна;
   - ферма;
   - прогоны ЛСТК;
   - прогоны прокатные;
   - балочная клетка;
   - оконные ригели;
   - подкрановая балка.
2. Проверить матрицу `knowledge/wiki/parity/module-parity-matrix.md`.
3. Не менять generated-файлы вручную.
4. Не менять формулы ради прохождения тестов.

## Следующие сценарии

### `SCN-BEAM-CELL-002`

Найти в `EXCEL-007` сценарий, где Excel дает допустимое решение не только по главной балке, но и по второстепенной балке/колоннам. Закрепить профиль, массу и стоимость.

### `SCN-WINDOW-RIEGEL-002`

Взять другой тип окна или другую высоту окна из `EXCEL-005`. Желательно закрепить не только первый профиль, но и диагностические коэффициенты по прочности/гибкости/прогибу, если их можно стабильно извлечь.

### `SCN-CRANE-BEAM-002`

Взять другой крановый сценарий из `EXCEL-006`: другая грузоподъемность или два крана. Отдельно не смешивать это с расчетом колонны.

### `SCN-PURLINS-002`

Взять сценарий прогонов со снеговым мешком, снегозадержанием или ограждением. Это важнее, чем добавлять еще один обычный сценарий.

### `SCN-COLUMN-002`

Закрепить выбранный профиль и массу колонны по одному понятному сценарию из `EXCEL-010`, а не только `N/M`.

## Критерий готовности к "Единому зданию"

Можно переходить к первому техническому каркасу раздела, когда:

- текущие тесты проходят;
- известно, какие модули дают расчетный результат;
- для каждого модуля зафиксировано, что именно считается oracle;
- открытые инженерные вопросы не скрыты из UI и wiki;
- подсчет количества элементов не смешивается с расчетом профиля.
