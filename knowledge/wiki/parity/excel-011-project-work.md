# EXCEL-011 — Проектные работы (стоимость и срок), конструктив «Великан»

Статус: `реализовано (ядро)`.

Источник: `EXCEL-011` — калькулятор стоимости проектных работ ИНСИ (файл
не коммитится; в репозитории только обезличенные формулы в
`src/calc/projectWork/workbook.generated.ts`).

## Назначение

Считает по разделу **КМ** (конструкции металлические):

- стоимость проектных работ, тыс. руб (`Z9`);
- срок проектирования, рабочих дней (`Z10`);
- удельную стоимость, тыс. руб/т (`Z17`, металлоёмкость Великана 35 кг/м²).

В проекте используется **только конструктив «Великан»**. Прочие ангары
(Спринт, Атлант, Крон) в подбор не идут: движок принудительно выставляет
тип здания = Великан (`AM7=3`) и флаг расчёта КМ (`AM8=TRUE`); колонки
других ангаров обнуляются гейтом исходной книги.

## Структура книги

Три листа: «Сроки и стоимость» (вход/выход), скрытый «Атлант, Великан»
(база ставок, 546 строк) и «Спринт» (для других ангаров, в Великан-пути
не используется, оставлен только ради общих формул `MAX`).

Ядро формулы (Великан):

```
стоимость = база(80 000) × страна × сейсмика × Σ(коэффициентов) / 1000 × (1 + издержки)
срок = стоимость / 180 × 20
```

`Σ коэффициентов` собирается из таблиц-справочников листа «Атлант,
Великан» (`INDEX/MATCH`, `CHOOSE`, `CEILING.MATH`): база по числу
пролётов, высота/ширина/длина по диапазонным таблицам, стены (матрица
материал × толщина × сейсмика × огнестойкость), окна/ворота/двери,
краны, лестницы, антресоли, перекрытия, парапет и т.д.

## Реализация

Воспроизведение через HyperFormula 1-в-1 (как crane-beam / window-riegel):

- `scripts/extract_project_workbook.py` — извлекает книгу в generated-TS
  (литералы `TRUE/FALSE` → функции, удаляется префикс `_xlfn.`);
- `src/calc/projectWork/engine.ts` — движок, книга кэшируется, между
  расчётами батчем переписываются входные ячейки;
- `src/calc/projectWork/__fixtures__/scenarios.json` — ground-truth из
  офлайн-оракула HyperFormula (10 сценариев);
- `src/calc/projectWork/engine.acceptance.test.ts` — сверка движка с
  оракулом.

Эталон оракула сверен с кэшированными значениями Excel: дефолтный файл
даёт `Z9=179.2`, `Z10=19.91` — совпадает.

## Связь с приложением

Вкладка `src/ProjectWorkApp.tsx`. Геометрия (пролёты, ширина, длина, шаг
рам, высота, форма кровли, опорный кран) берётся из общего
`BuildingContext`; проектные опции (стены, проёмы, сейсмика, издержки,
г/п кранов) задаются на вкладке.

## Реализовано / отложено

Ядро: геометрия, высота, кровля, стены, окна/ворота/двери, опорный и
подвесной краны, сейсмика, издержки.

Отложено (вторым заходом, поля пока на дефолтах книги): лестницы (8
вариантов), антресоли (×3) и перекрытия, перегородки (ГВЛ/сэндвич),
парапет, степень огнестойкости, водосточная система, снегозадержание,
ограждение кровли. Движок их поддерживает (книга считает их при подаче
соответствующих входов) — нужно лишь добавить элементы управления.

## Открытые вопросы

- Уточнить смысловую шкалу «толщина стен (индекс)» и «г/п крана (индекс)»
  — сейчас передаются как числовые коды книги без человекочитаемых
  подписей.
- Для многопролётных зданий приложение принимает равные пролёты
  (`spanWidth2 = span_m`); проверить, нужны ли разные ширины пролётов.
