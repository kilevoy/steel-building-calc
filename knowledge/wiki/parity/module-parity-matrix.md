# Матрица Excel-parity по расчетным модулям

Дата среза: 2026-05-25.

Цель страницы: перед переходом к разделу "Единое здание" показать, какие модули уже имеют автоматическую сверку с Excel-oracle, какие поля реально проверяются тестами, и где еще нельзя утверждать полное совпадение 1 в 1.

Важно: эта матрица не меняет расчетную логику. Она фиксирует уровень доверия к текущим acceptance tests.

## Что уже можно считать закрепленным

1. У каждого основного расчетного раздела, кроме сводки, есть хотя бы один автоматический acceptance или smoke/parity тест.
2. Тяжелые Excel-generated модули подкрановой балки и оконных ригелей проверяются через публичный расчетный API, а не через UI.
3. Последний слой тестов для `beamCell`, `windowRiegel` и `craneBeam` опирается на generated expected values, а не на вручную продублированные числа.
4. Для прогонов закреплены важные Excel-поведения: `autoMaxStep_mm = 1500`, отказы семейств `2ТПС/2ПС` в сценарии `SCN-PURLINS-001`, выбор `Z 350x2,5`, масса с распорками и расчет осевой ветровой нагрузки для прокатного подбора.
5. Для фермы закреплено, что сценарий должен идти с `loadAddition_pct = 15`; прежнее расхождение профилей было ошибкой входных данных теста, а не формул.

## Где еще нельзя говорить "полностью 1 в 1"

### Колонна

Есть хорошая численная база по `N/M/снег/ветер`, но нужна отдельная сверка выбранного профиля, массы и диагностик по `EXCEL-010`. Также остается открытым вопрос типов колонн, фахверка и учета кранов при подсчете количества элементов здания.

### Ферма

Сценарий `SCN-TRUSS-001` хорошо закрепляет профильный подбор и массу, но горизонтальная реакция `H` не подтверждена Excel-oracle. Нельзя подставлять `H = 0` как окончательное инженерное решение.

### Прогоны

Сценарий `SCN-PURLINS-001` хорошо покрывает базовую ветку, но нужны дополнительные сценарии:

- снеговой мешок;
- прогон под снегозадержание;
- прогон под ограждение;
- разрезной/неразрезной прогон, если это поведение есть в Excel и должно попасть в приложение;
- другие типы кровли и покрытия.

### Балка покрытия / балочная клетка

Сценарий `SCN-BEAM-CELL-002` закрывает базовую полную ветку: Excel дает допустимые ВБ, ГБ и К. Остаются нужны дополнительные варианты по другим типам перекрытий, шагам и конструктивной схеме.

### Оконные ригели

Проверяются первые наблюдаемые профили и нагрузки. Нужно извлечь из Excel дополнительные диагностические коэффициенты: гибкость, прочность, прогибы, а также сценарии для других типов окон.

### Подкрановая балка

Базовый сценарий закреплен хорошо. Нужны сценарии:

- другой грузоподъемности крана;
- два крана, если Excel это поддерживает;
- уточнение вопроса шага ребер: использовать исходный `B19` или подобранный `D19`;
- связь с крановыми полями в модуле колонны.

## Рекомендуемый порядок следующих тестов

1. `SCN-WINDOW-RIEGEL-002`: добавить сценарий по другому типу окна или высоте окна, включая диагностические коэффициенты.
2. `SCN-CRANE-BEAM-002`: добавить сценарий с другой грузоподъемностью или двумя кранами.
3. `SCN-PURLINS-002`: добавить сценарий со снеговым мешком или снегозадержанием.
4. `SCN-COLUMN-002`: закрепить выбранный профиль и массу по одному понятному Excel-сценарию.

## Правило для будущих изменений

Если модуль меняется по формуле, ранжированию или входным данным, сначала нужно понять, какой источник является oracle:

- generated expected из workbook;
- frozen fixture;
- вручную описанный сценарий в `knowledge/wiki/parity/scenarios/`;
- решение пользователя или ГИПа.

Если source of truth неясен, изменение нельзя маскировать обновлением expected values. Нужно занести вопрос в `knowledge/lint.md` или `knowledge/wiki/parity/known-differences.md`.
