# SCN-COLUMN-002 — колонна, первый выбранный профиль

Статус: `accepted for partial automated parity test`.

Источник: `EXCEL-010`.

Назначение: закрепить совпадающую часть первого результата подбора колонны для default Excel-сценария. Этот сценарий не закрывает вопрос массы колонны, потому что там обнаружено расхождение длины/массы, связанное с геометрией колонны.

## Входные данные

Используется сценарий `SCN-COL-DEFAULT` из `src/calc/__fixtures__/column-scenarios.json`.

## Закрепленные Excel anchors

| Показатель | Значение |
|---|---:|
| Профиль | 35 Б1 |
| Сталь | С355Б |
| Количество распорок | 3 |
| Масса 1 п.м. | 41.4 кг/м |
| Максимальный коэффициент использования | 0.9742299766 |
| Определяющий критерий | по σ уст X |

## Автоматический тест

Тест добавлен в `src/calc/engine.acceptance.test.ts`.

Проверяются профиль, сталь, число распорок, масса на погонный метр, max utilization и определяющий критерий.

## Известное расхождение

Масса колонны и итоговая масса не закреплены этим тестом.

Наблюдение:

- Excel-сценарий фиксирует массу колонны `547.515 кг`;
- текущий engine для профиля `35 Б1` считает `columnMass_kg = 476.1 кг`;
- разница соответствует разной расчетной длине элемента: engine использует `height_m = 11.5`, а Excel-масса выглядит как расчет по большей длине.

Это похоже на инженерный вопрос: длины колонн зависят от уклона кровли, типа кровли и положения колонны. Нельзя менять формулу массы вслепую. Нужно отдельно разобрать Excel-ячейки длины колонны и правила для крайних/средних/фахверковых колонн.
